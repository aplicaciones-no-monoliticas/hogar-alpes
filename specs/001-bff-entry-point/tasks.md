# Tasks: BFF — un solo punto de entrada y trazabilidad por petición

**Input**: documentos de diseño en `specs/001-bff-entry-point/` (`plan.md`, `spec.md`, `research.md`, `data-model.md`, `contracts/bff-api.md`, `contracts/correlacion.md`, `quickstart.md`) y `.specify/memory/constitution.md`.

**Prerrequisitos**: `plan.md` y `spec.md` (presentes).

**Tests**: SÍ se generan. El plan los compromete (FR-036, Constitución VI y «Flujo y puertas de calidad»): pruebas `pytest` del BFF con servidores HTTP falsos **reales**, pruebas `pytest` de cada servicio tocado, comprobaciones estáticas, `newman` y `escenarios/bff.sh`.

**Organización**: por historia de usuario. Las dos historias P1 (US1 reenvío, US5 aislamiento) van primero; luego US2 (compuestos), US3 (correlación) y US4 (Postman).

## Formato: `[ID] [P?] [Story] Descripción con ruta`

- **[P]**: se puede hacer en paralelo (archivos distintos, sin depender de una tarea incompleta).
- **[Story]**: US1…US5 (solo en las fases de historia).
- Todas las rutas son relativas a la raíz del repositorio (`hogar-alpes/`).

## Convenciones que aplican a TODAS las tareas

- **Aserciones contra literales** (Constitución VI): nunca compares un valor con el objeto que la propia prueba acaba de producir; escribe el código, el cuerpo o el id esperado como literal.
- **Cero dependencias nuevas** (FR-009, CA-2.2): solo `Flask==3.0.3`, `gunicorn==22.0.0`, `pytest==8.2.0` y biblioteca estándar (`urllib.request`, `concurrent.futures`, `contextvars`, `re`, `uuid`, `http.server`).
- **Prohibido en el BFF**: SQLAlchemy, psycopg2, `pulsar-client`, volúmenes, `DATABASE_URI`, `BROKER_HOST`, estado en disco o en memoria compartida entre peticiones.
- **Prohibido en los servicios de dominio**: cliente HTTP, `http://`, variables de entorno hacia otro servicio o hacia el BFF, la palabra `bff` en archivos `.py` (código o comentarios) ni en variables de entorno de `docker-compose.yml` (la única mención permitida en `docker-compose.yml` es el nombre de red `red-bff-<svc>`), y el identificador de correlación en `dominio/` o en `dto.py` (FR-022, FR-030).
- **Lo que no se pueda ejecutar se anota como PENDIENTE, nunca como PASA** (por ejemplo, sin Docker o sin `saga-log`).
- Textos de usuario y comentarios del código en español, como el resto del repositorio. Comentarios: solo el porqué no obvio, una línea.
- Pruebas de servicio: `cd servicios/<svc> && python -m pytest`.
